# sidge-lunch

Where can I get lunch on Sidgwick site, and what is it today?

> **This is an unofficial, independent project.** It is not affiliated with, endorsed by, or run by the
> University of Cambridge, any of its faculties or departments, or any college or vendor listed. Menus are
> collected automatically from the vendors' public web pages and may be incomplete, wrong or out of date.
> Always check with the vendor, especially about allergens and dietary requirements.

> **Vibe coded using [Claude](https://claude.ai/code).** Most of this code was written by an AI assistant
> and has had limited human review. Expect rough edges, and don't rely on it for anything important.

A static site with two views of the same data:

- **Map**: pick your faculty and see walking times to each vendor. Click a vendor for today's menu.
- **Dashboard**: today's lunch at every vendor, filterable by dietary label and price, sortable by walking
  time or price.

## How it works

```
GitHub Actions (cron)                        GitHub Pages
┌───────────────────────────────┐            ┌──────────────────────┐
│ scraper/  fetch each menu page │  commits   │ web/ (Vite + Leaflet)│
│ → vendor adapter → common JSON ├──────────► │ reads data/*.json    │
│ → data/menus.json if changed   │  deploys   │                      │
└───────────────────────────────┘            └──────────────────────┘
```

| Path | What it is |
| --- | --- |
| `data/vendors.json` | Vendors: name, menu URL, location. Edited by hand. |
| `data/faculties.json` | Sidgwick Site faculties and their buildings' locations. Edited by hand. |
| `data/menus.json` | Generated by the scraper. Don't edit. |
| `data/walking.json` | Generated walking routes (faculty → vendor). Don't edit. |
| `scraper/sidge_lunch/schema.py` | The common menu format every adapter produces. |
| `scraper/sidge_lunch/adapters/` | One HTML parser per vendor. |
| `scraper/sidge_lunch/run.py` | Fetches every vendor, updates `menus.json` only when something changed. |
| `scraper/sidge_lunch/walking.py` | Computes walking routes via OSRM (OpenStreetMap). |
| `web/` | The site. |

### Workflows

- **Scrape menus** (`scrape.yml`) runs every 30 minutes through the morning and every 3 hours otherwise. If
  `menus.json` changed it commits and redeploys. Menu pages don't say when they change, so the scraper
  compares a hash of the parsed menu instead.
- **Walking times** (`walking.yml`) recomputes routes when `faculties.json` or `vendors.json` changes, or on
  demand. Until it has run, the site shows straight-line estimates marked "≈".
- **Deploy site** (`deploy.yml`) builds `web/` with `data/` and publishes to GitHub Pages.
- **CI** (`ci.yml`) runs the scraper and web tests.

### Menu data

Each vendor in `menus.json` has a `status`:

- `ok`: parsed successfully. `updated_at` is when the menu content last changed.
- `error`: the latest fetch or parse failed. The last good menu is kept and the site says it may be stale.
- `unsupported`: no adapter written yet. The site links to the vendor's page.

Dietary labels are only recorded when the vendor publishes them. Adapters must never guess them from dish
names. Items without a published price show "price not listed".

## Adding a vendor

1. Add it to `data/vendors.json` (id, name, menu URL, coordinates).
2. Save a copy of its menu page to `scraper/tests/fixtures/<id>.html`.
3. Write `scraper/sidge_lunch/adapters/<id>.py` with `parse(html, today) -> list[Day]`, register it in
   `adapters/__init__.py`, and add a test against the fixture.
4. Merge to `main`. Walking times are recomputed automatically.

## Development

```sh
# scraper
cd scraper
python -m venv .venv && .venv/bin/pip install -e '.[dev]'
.venv/bin/pytest
.venv/bin/python -m sidge_lunch.run --only selwyn   # updates ../data/menus.json

# site
cd web
npm install
npm run dev      # serves ../data; SIDGE_DATA_DIR=/path/to/sample npm run dev to use other data
npm test
```

## One-time setup

In the repository settings, set **Pages → Build and deployment → Source** to **GitHub Actions**.

## Etiquette

The scraper identifies itself with a User-Agent linking to this repository, respects `robots.txt`, and
fetches each page at most every 30 minutes. If you run a listed vendor and would like it removed or changed,
please open an issue.
